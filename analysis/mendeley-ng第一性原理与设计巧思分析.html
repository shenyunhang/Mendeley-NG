1根本问题与四条基本事实

根本问题（一句话）一个终将失效的外部服务（Mendeley API / 被冻结的 1.19.8 客户端），要可靠地喂养一份必须永远可读、可搜、可带走的本地文献库。 README.md:10-27：云端是同步源不是宿主；API 关掉、token 过期或断网时屏幕上的库照常能用，但也诚实承认「暂时仍要依赖它的 API」。这个「既依赖又不能依赖」的张力是所有设计的来源。
基本事实

A · 本体论 / 工程论：磁盘是唯一真相

状态必须能从磁盘重新推导，进程内快照一律不可信。
推翻：「同步 = 用云端答案覆盖本地缓存」「把配置/阅读位置缓存在闭包里省一次读」。外部还有第二个窗口、恢复流程、手改文件。

基本事实

B · 认知论：跨 IPC 一切都是输入

危险集合不是可枚举的清单。
推翻：「开了 contextIsolation 就安全」「列出 file:/javascript: 过滤掉就行」——隔离的是代码，不是载荷。

基本事实

C · 工程论：PDF 文本昂贵且有损

offset 必须与它描述的文本在同一份、同一次写里度量。
推翻：「用文件字节偏移就行」「先 lowercase 再算长度无妨」。一个汉字 3 字节但 1 个 code unit；İ 小写后变成两个 code unit。

基本事实

D · 认知论 / 时间：异步结果属于出发时的世界

promise 不可取消，作废只能靠「归属标记 + 代次」。
推翻：「clearTimeout 就取消了请求」「把 state 清空就等于取消」「值没变就说明答案还有效」。

事实验证e419fda 提交信息是 B 的原始表述；HANDOFF.md:266-269 记 A 的事故（阅读位置缓存让 load 与 set 答案不一致）；fulltext.ts:575-577 记 C 的 U+0130；viewGeneration.ts:23-32 用 generation++ 而非值比较实现 D。

sameIndexedFile（mtime+size，追加路径额外比 file）、snippetAround（先按原文本切片再折叠空白）、progressAllowed（force 收尾消息）；全文表的形状、偏移定位、页码与 worker 故障判定也下沉到 shared/。

为什么必然事实 A 与 C：两套索引元数据格式不同，但「文件变没变」「片段从哪切」「何时报告进度」是同一批事实；各写一份迟早一处改了另一处没改。把只读规则与持有 fs、worker 的状态机分开后，前者不需要启动 Electron 或造 PDF 就能测。

5代价与边界（直面缺陷）

① 约束强度从「不可能错」降级为「错了会被拦住」safeConfigPatch 挡得住未知键，挡不住白名单内值语义上是错的（pdfDir 指向不存在的目录）；reconcileSyncWrite 依赖「写盘前重读」这一次读与写之间不再有第二个写入者，HANDOFF.md 第 9 节承认原子写不是并发安全的。
② 通用性换来的性能代价与页数取舍默认只索引每篇前 3 页，整篇抽取的文本量是前几页的数倍；搜不到时必须说清「读了多少页、这不等于库里没有」，且改页数会丢索引。
③ 开放词汇的语义治理成本BibTeX 没有独立类型名的网页 / 专利 / 程序只能写成 @misc，导回变成 generic；DOC_TYPES 白名单之外的值显示「（未设）」而不是顶成第一项。
④ 可验证性仍有未覆盖区间fulltext.ts 的表形状、偏移定位、页码与 worker 故障判定已下沉到 shared/fulltextRules.ts 并配固定输入单测；仍主要靠 smoke 源码串断言与真实库自检守着的是写入状态机（busy / deferred / pending）、App.tsx 剩余状态簇与 smoke.ts 两段 UI 驱动链。smoke 需要真实窗口，无法进 CI。
⑤ 剩下的边界在门禁上书目、参考文献、篇内查找与保存搜索共用 normaliseQuery，两套索引共用 shared/indexedFileRules.ts。仍重复的是 worker 定位 / 超时竞速 / 清理（fulltext.ts:33-60 对 refsindex.ts:119-143）与 IPC 失败形态（部分返回 {error}、部分直接 reject），两者都被冒烟源码串断言与渲染层两种错误处理路径绑着。
⑥ 具名失败门受计数判据约束smoke.ts:5824-5852 对五个产品文件统计 6 个 ignoreFailure + 6 个 reportFailure，并要求每个 FAILURE reason 在这五个文件或 smoke 自身出现。新增一个理由而不改这道门禁会让冒烟变红；扩展失败门必须先改判据，不能只加调用点。

6综合结论

19 项巧思覆盖表示（单一 View + payload、归一化副本）、写入（四快照裁决、原子写、双锚点、checkpoint）、审计（具名失败门、索引自审、差分回归）、解释（空态说明读了多少页、批量报失败名单、format/budget 各说各话）、演化（编译期穷尽的白名单、可选 hay 兼容旧缓存、纯规则先配单测再改接线）、检索（近似命中借用原文位置、第二套索引与转码副本、追加而非替换、多标签投影）六个维度。

系统约束因为外部服务不可靠、跨进程输入不可信、PDF 文本昂贵且有损、异步结果不可取消，所以这个系统选择让磁盘做唯一的裁判，让所有规则只留一份且可测，让每一次写入都能被重读与解释，让每一个在途答案都带着它出发时的标签。

未收敛的部分已不在「规则有没有」，而在「哪道门禁允许改」：五份 JSON 无 schema 版本与迁移、IPC 失败形态不统一、两个索引的 worker 生命周期仍各写一份、具名失败门受 6/6 计数判据约束。抽共享规则仍须遵守 HANDOFF 第 4 节「先逐值差分，且探测器先证明抓得到旧写法」。
